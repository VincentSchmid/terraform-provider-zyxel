# zyxel_dhcp_reservation (Resource)

Manages one static DHCP reservation on the router. The router binds reservations to its default LAN bridge; that bridge is fixed by the provider.

Reservations are created enabled on the LAN bridge (`BrWan = "Default"`).
Only `enabled = true` is supported in configuration. The router's observed
enabled state is refreshed, so external disabling is detected as drift.

Every configurable change requires replacement. Replacement deletes the old
reservation before creating its successor, so a creation failure can leave
it absent. Do not use `create_before_destroy` when retaining the same MAC.

## Example Usage

```terraform
resource "zyxel_dhcp_reservation" "nas" {
  mac_address  = "02:00:00:00:00:20"
  ipv4_address = "192.168.1.20"
}
```

## Schema

### Required

- `ipv4_address` (String) IPv4 address reserved for this MAC address. Changing it replaces the reservation.
- `mac_address` (String) Canonical uppercase colon-separated MAC address. This is the resource identity and import key.

### Optional

- `enabled` (Boolean) Whether the reservation is enabled. It is configurable as `true` and defaults to `true`; a router-reported disabled value requires replacement.

## Import

Import by MAC address. Colon- or hyphen-separated six-byte MAC notation is
normalized to uppercase colon-separated form; use that canonical form in
configuration.

```shell
terraform import zyxel_dhcp_reservation.nas '02:00:00:00:00:20'
```

An existing reservation must be imported before Terraform creates it.
Multiple rows matching the same MAC are an error; the provider never chooses
one arbitrarily. Missing rows leave state on refresh, and deletion of an
already absent reservation succeeds. Router row indexes are refreshed before
deletion rather than retained as identity.

Operations sharing a provider client are serialized. Separate Terraform
processes and router UI edits still require coordination. Local encrypted
mock tests cover this lifecycle; live DHCP writes remain unverified.
